CNN-Based Image Classification
EC ENGR 149 · Foundations of Computer Vision Python · PyTorch

CNN-Based Image Classification — CIFAR-10

Python PyTorch

Built and trained a convolutional neural network from scratch in PyTorch for 10-class image classification, then swept batch size and epoch count to study the trade-off between gradient noise and convergence speed.

  • Best configuration (batch size 16, 20 epochs) reached 65.7% test accuracy, versus 55.5% at only 5 epochs with the same batch size — most of the accuracy gain came from training longer, not from architecture changes.
  • At a fixed 5 epochs, the smaller batch size (4) outperformed the larger one (58.1% vs. 55.5%) — noisier, more frequent gradient updates helped early on. That reversed once given enough epochs, where the larger batch's steadier gradient estimates pulled ahead (65.7% vs. 61.2% at 20 epochs).
  • Explained and applied core CNN mechanics: how padding and kernel size determine output size, why max pooling has no learnable parameters, and why batch normalization uses running statistics at inference instead of the current batch's mean/variance.

Robust Geometric Estimation
EC ENGR 149 · Foundations of Computer Vision Python · NumPy · OpenCV

Robust Geometric Estimation — SIFT, RANSAC & Homography

Python NumPy OpenCV

Full correspondence pipeline built from primitives: SIFT keypoint detection and descriptor matching, a from-scratch RANSAC loop for robust homography estimation, and inverse warping with bilinear interpolation to stitch image pairs into a single panorama.

  • Implemented direct linear transform (DLT) homography estimation from raw correspondences, then RANSAC to separate true matches from spurious ones.
  • Stitching without RANSAC visibly breaks on outlier matches — a direct, visual demonstration of why robust estimation matters, not just a theoretical footnote.
  • Extended the same approach to insert new content into a target image via homography (compositing a name plate into a photograph using four corner correspondences).
  • Also implemented the eight-point algorithm for essential matrix estimation and 3D point reconstruction from stereo correspondences (2.7% mean reprojection error).

Feature Detection
EC ENGR 149 · Foundations of Computer Vision Python · NumPy

Feature Detection — Edges, Blobs & Corners

Python NumPy

A ground-up image-filtering stack: 2D convolution, Gaussian/median/bilateral filtering, gradient-based edge detection, Laplacian-of-Gaussian blob detection, and Harris corner detection with non-maximum suppression — every operator derived and implemented by hand.

  • Compared average, Gaussian, and median filtering for denoising; median filtering won on both quantitative error (lowest relative L1 distance) and visual edge preservation.
  • Derived a bilateral filter from first principles to smooth flat regions while keeping edges sharp — the same idea behind "cartoonize" filters in consumer photo apps.
  • Built full non-max suppression for Harris corners: threshold → sort by response → greedy spatial suppression, from scratch, no library calls.

Semantic Matching & Reasoning
M146 · Intro to Machine Learning Python · HF Transformers · PEFT / LoRA

Semantic Matching & Reasoning with Language Models

Python Transformers PEFT / LoRA

Two-part final project comparing how far you can push a small language model with architecture, fine-tuning, and prompting alone.

  • Paraphrase detection (PAWS): a bi-encoder baseline (MiniLM + logistic regression) hit 61.8% test accuracy — it can't see token-level word-order swaps that flip meaning. Fine-tuning a DistilBERT cross-encoder pushed that to 81.9%, matched by few-shot prompting a 1.5B instruct model (81.5%) with zero training.
  • Math reasoning (GSM8K): LoRA fine-tuned Qwen2.5-1.5B on 1,000 then 2,000 examples, taking base-model accuracy from 36% → 47% → 49%, training under 0.15% of total parameters. Diagnosed the model's actual failure modes (percentage misinterpretation, arithmetic slips, problem misreads) before and after tuning.
  • Prompt engineering: a "reread the problem first" prompt alone lifted base-model accuracy 44% → 60% — matching what fine-tuning achieved, with no training.

Research Radar

Next.js TypeScript Tailwind CSS Clerk Supabase Oxylabs Google Gemini Vercel AI SDK

An automated AI research digest: it scrapes academic papers and technical blog posts on a schedule, scores each one for difficulty, and surfaces developer-focused takeaways so keeping up with a fast-moving field doesn't require manually reading every paper.

  • Fully automated pipeline — sources are scraped hourly via the Oxylabs Web Scraper API, then analyzed by Google Gemini (via the Vercel AI SDK) every 15 minutes, no manual curation step.
  • Each paper gets an AI-generated 1–10 difficulty score (beginner / intermediate / expert) plus three developer-focused key takeaways, with a full analysis page breaking down methodology and confidence.
  • Semantic search over the whole corpus via Supabase Postgres with the pgvector extension, so related research surfaces by meaning, not just keyword match.
  • Clerk-based authentication gates the protected routes; the whole app is deployed on Vercel with scheduled cron jobs driving the scrape-and-analyze loop.

Website Template Cloner
Personal Project TypeScript · Node · Playwright · Next.js

Website Template Cloner

TypeScript Node Playwright Next.js

An agent-driven pipeline that turns any webpage into a reusable front-end template: it captures the rendered DOM, every stylesheet and a full-page screenshot, measures how the page is built, and emits a self-contained Next.js app with placeholder copy and imagery — the construction reproduced, the content left behind.

  • Resolves exact values without staying attached to the live page: the captured DOM is reloaded with the captured CSS in a headless browser, so getComputedStyle resolves the real cascade offline and every run is reproducible from the same bytes.
  • Every colour, spacing, type-scale and breakpoint value is cited to a selector and property, or written as UNVERIFIED — never guessed.
  • Placeholder substitution is enforced by an idempotent script, matching original word counts and image dimensions so the template still measures like the page it came from — the apple.com/iPhone rebuild lands within 1px over a 12,967px page.
  • Reconnaissance, per-section specs, parallel builder agents, visual band-by-band diffing and the static→Next.js conversion are wired together as a Claude Code skill.

Yu-Gi-Oh! RAG Chatbot
Personal Project LangChain · LangGraph · ChromaDB · Ollama · Streamlit

Yu-Gi-Oh! RAG Chatbot

LangChain LangGraph ChromaDB Ollama Streamlit

A Retrieval-Augmented Generation chatbot that answers questions over the full Yu-Gi-Oh! card database (~14,500 cards) using a locally-hosted LLM — no paid APIs, no external inference.

  • Hybrid retrieval combines semantic vector search (Sentence Transformers + ChromaDB) with exact metadata filtering on archetype/card type, avoiding hallucinated results on structured queries like "list all Blue-Eyes cards."
  • A LangGraph ReAct agent handles tool-calling and intent classification, routing greetings away from the retrieval pipeline and resolving follow-up questions ("what about that one's ATK?") from cached sources and chat history.
  • Generation is grounded strictly in retrieved context — the prompt constrains the LLM (Qwen2.5-7B via Ollama) from inventing card names not present in the retrieved chunks.

German Whisper Transcriber

Python Streamlit Whisper PyTorch

A Streamlit app that transcribes German audio/video locally using OpenAI's Whisper model, then translates the transcript to English — built for cases where content shouldn't leave the machine to get transcribed.

  • Runs Whisper fully locally with a model-size selector (tiny → large) and automatic GPU/CPU detection via PyTorch, trading speed for accuracy as needed.

Personal Project Python · Ollama · MCP · FastAPI

Google AI MCP Agent

Python Ollama Gemini MCP FastAPI Playwright

A local Ollama agent that calls Google's free-tier AI tools — AI Studio/Gemini, Stitch, NotebookLM, and AI Mode search — as tools over MCP, with a hand-rolled Ollama↔MCP bridge and an OpenAI-compatible API in front so any OpenAI-client chat UI (Open WebUI, etc.) can use it as a real tool-calling backend.

  • Hand-rolled translation layer between Ollama's native tool-calling schema and MCP, since Ollama has no first-class way to talk to arbitrary MCP servers.
  • Routes tool calls across five MCP servers — an echo sanity-check, AI Studio (Gemini API), Stitch (HTTP), NotebookLM, and AI Mode search (both vendored, browser-automated via Playwright) — through one client manager.
  • Per-message tool scoping (/tools stitch, /tools all) keeps default requests to a local 8B model fast, since sending every server's full tool schema on every turn pushed even trivial replies to 60–150+ seconds.
  • Every response ends with a footer showing which tools were offered, connected, and actually fired that turn, so tool usage is visible directly in the chat.
