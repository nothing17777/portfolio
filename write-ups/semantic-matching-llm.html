M146 · Introduction to Machine Learning — Final Project

Semantic Matching & Reasoning with Language Models

Two questions, one theme: how far can you push a small language model using architecture, fine-tuning, and prompting alone — on detecting paraphrases, and on solving grade-school math word problems.

Part A — Why word overlap alone can't detect paraphrases

Measuring the Jaccard similarity (shared words / all words) between sentence pairs in the PAWS dataset showed something important: paraphrase and non-paraphrase pairs have almost identical overlap distributions, both concentrated at high overlap. That's because PAWS is specifically built from sentences with the same words in a different order — meaning is changed by rearrangement, not by word choice, so a method that only counts shared words is blind to the label. That motivated the hypothesis that a model comparing token-level order (a cross-encoder) should beat one that only compares whole-sentence summaries (a bi-encoder).

Baseline: comparing sentence embeddings directly

A bi-encoder baseline — MiniLM sentence embeddings for each sentence separately, combined into a feature vector and classified with logistic regression — reached only 61.8% test accuracy. It can't directly compare tokens across the two sentences, only their aggregate meaning, so it misses exactly the word-order swaps PAWS is built around.

Fine-tuning a cross-encoder

Fine-tuning DistilBERT end-to-end on sentence pairs — so the model can attend across both sentences at the token level — jumped accuracy to 81.9%. The trade-off: roughly 60× slower per prediction, since every pair needs a full forward pass through the transformer instead of a cached embedding lookup.

Looking specifically at the cases where the two models disagreed, the cross-encoder was correct 76% of the time — catching subtle subject/object swaps and single-word insertions (like the addition of "also") that quietly flip meaning without the bi-encoder noticing.

Prompting an instruction-tuned model instead of training anything

Zero-shot prompting a 1.5B instruction-tuned model reached 74.5% accuracy with no training at all. Adding four labeled examples to the prompt (few-shot) pushed that to 81.5% — nearly matching the fine-tuned cross-encoder's 81.9%, with zero gradient updates.

Prompt wording turned out to matter a lot: a second, only slightly differently worded zero-shot prompt collapsed accuracy to exactly 50% — the model started predicting "not paraphrase" for every single example. Small wording changes can cause a total behavioral collapse, which is a real argument for testing prompts carefully before trusting one.

Part B — How well can a small model do grade-school math?

The un-tuned 1.5B base model scored 36% on a 100-question GSM8K subset. Reading through its failures showed a consistent pattern: the model usually sets up the problem correctly, then loses points to an arithmetic slip (15 + 25 = 4 instead of 40), a misread percentage (treating a 150% increase as 15%), or a step it silently forgets (not restarting a download from zero after an interruption).

Fine-tuning efficiently with LoRA

Instead of updating all 1.55 billion parameters, LoRA fine-tuning adds small low-rank adapter matrices to the attention layers and trains only those — about 2.18 million parameters, or 0.14% of the model. Training on 1,000 examples raised accuracy from 36% to 47%; adding another 1,000 examples (2,000 total) pushed it slightly further to 49%, with most of the gain clearly front-loaded in that first batch of data.

Comparing the fine-tuned model against the same three failure cases from before: it fixed some of the raw arithmetic slips, but still made new mistakes on multi-step problems — fine-tuning improved reliability on format and execution more than it fixed deeper misreadings of what a problem was actually asking.

Does few-shot prompting help a model that's already fine-tuned?

Somewhat counterintuitively, adding worked examples to the prompt slightly hurt accuracy for both the base model (38% → 33%) and the fine-tuned model (49% → 48%). At this model size, a longer prompt seems to cost more in context budget than the extra examples give back — a pattern that's known to reverse for much larger models.

A better prompt alone matched what fine-tuning achieved

Testing six prompt variations on the un-tuned base model, the best one — explicitly instructing the model to reread the problem and list its numbers before solving — lifted accuracy from 44% to 60%, beating the LoRA fine-tuned model's 49%, entirely without training. Rigid, over-structured prompts actually performed worse than a plain one, suggesting the model was spending effort conforming to format instead of reasoning through the math.
